## Prioritized findings and exact plan changes

1. **P1 — Define what a fresh-checkout, offline success actually proves.** The quickstart names world rendering, lint and M0 scoring, but these are separate checks: scoring M0 fixtures does not evaluate the newly rendered world or exercise the PDLC harness. `pyproject.toml` requires Python 3.12 and explicitly notes the initial tiktoken encoding download. The pilot ingestion tool restricts its output to `build/pdlc-pilot` and consumes locally prepared authoring inputs. Add to the quickstart row: “One copyable command sequence from repository root, expected output and exit status, explicit dependency/token-cache bootstrap versus offline execution, and a statement of which pipeline each command exercises.” Add a clean-checkout verification criterion: no reliance on existing ignored `build/`, `runs/`, authoring ledgers or caches except separately declared setup prerequisites. Use fresh output directories for commands that support them; do not suggest every pilot script accepts arbitrary destinations.

2. **P1 — Make activation and acceptance separate steps with explicit owners.** “Candidate vs accepted release” can collapse several different decisions. `harvest.py` validates review identity, snapshot binding and delegated scope, keeps unspecified assertions proposed, and explicitly performs no ACTIVE switch. `memory.py` selects an explicit release or ACTIVE and permits accepted assertions to operate. Corpus ingestion labels its output `loaded_development_candidate_not_frozen`; executable bundle validation separately requires independent acceptance for evaluation freeze. Amend routing-memory to include a state/authority table: source declaration → proposal → scoped reviewer decision → release assembly → runtime selection. Amend corpus-and-hubs with candidate audit/ingestion versus evaluation freeze. For each transition name the artifact, responsible role, check and command, or state that no automated transition exists. Keep human task acceptance and boundary-gold acceptance in scoring, linked from these tables.

3. **P2 — Put the two evaluation systems in the navigation, not just an accuracy footnote.** The root README still leads with M0/M1 historical framing and says world gold is independently audited later, while its own exit table records an open audit. Add a two-row “choose your path” table to the lab index and architecture: reference retrieval/world evaluator versus evidence-answer PDLC agent comparison. Include inputs, visible tools, private gold, output, scorer and claim limits. Give scoring separate sections for world/reference metrics and agent mechanical/semantic scoring, with links to their owning implementations. The root pointer should be prominent and label the remaining milestone material historical; a pointer at the bottom leaves conflicting current-state claims as the first impression.

4. **P2 — Assign concepts and commands to a single owner to prevent drift.** Agent-harness, scoring and runbook currently overlap on delivery, ledger, scoring and acceptance. Add this ownership rule to the plan: architecture explains flows and boundaries; subsystem pages own contracts and invariants; quickstart owns the minimal offline sequence; runbook owns operational command sequences and recovery; scoring owns interpretation and acceptance rules; codebase-map is a source/test index only. Subsystem pages may show small contract examples but link to runbook commands. This keeps eleven pages navigable without requiring additional pages or duplicating schemas.

5. **P2 — Specify recovery and portability limitations as concrete runbook content.** `run_agent_campaign.py` stops on unknown live dispatch, unreconciled usage, authentication limits or failed dispatch; terminal completion still leaves quality scoring pending. `run_quality_evaluation.py` pins a developer-local Claude binary, uses subscription credentials/macOS Keychain fallback and imports calibration fixtures from tests. Add a compact symptom → evidence file → safe next action table covering these stops, changed runtime/proof hashes, unavailable pilot inputs, invalid judge output and changed saved judge packets. Document the distinction between rerunning a resumable driver and reconciling an unresolved dispatch; do not promise automatic recovery. Mark the quality driver a local reference workflow, and distinguish offline saved-answer checks from semantic judging that invokes inference.

6. **P2 — Separate extension contracts from executable support.** `agent_contract.py` rejects adapters other than `claude_code`; `agent_session.py` creates an empty workspace. Add a support matrix near the top of extending: implemented evidence-only Claude path, generic reusable bundle/connector contracts, and future local coding/Codex/Pi adapter work. Explain extension inputs, validators and relevant tests, but give no runnable commands implying future adapters work. Link the supported path directly from the index so engineers need not infer it from historical experiments.
