**1. Pillars of routing intelligence**

Findings, ranked by design impact:

1. **High — Define one trusted request execution context.** Policy, routing, retrieval, assembly, and escalation are separate components, but no contract owns their shared tenant, principal, effective scope, absolute deadline, resource reservations, and pinned versions. The lab illustrates the consequence: retrieval starts its deadline *after* D2; Round 3 receives another configured deadline; the broker uses its profile deadline. Memory routing counts searches against `arm.calls`, while fetches consume additional calls. Packing uses the requested token budget without applying `arm.response_tokens`.  
   **Change:** introduce a trusted `ExecutionContext` and budget ledger spanning every stage, including retries, decomposition, searches, fetches, model calls, and response serialization. Make project scope narrowing explicit rather than treating it primarily as resolution context. [HLD §§5.1, 6.5, 14](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/hld.md:147); [pipeline.py, `retrieve` and `_ask`](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/pipeline.py:134); [routing.py, budget loop](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/routing.py:209); [broker, `decide`](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_run/system_one_broker.py:149)

2. **High — Safe defaults are not consistent across the documents or packing boundary.** HLD D6 estimates incompatibility within matching scope/version and defaults to `possible_conflict`; provider §12 estimates several material relationships, including differences across versions/environments, and leaves uncertain candidate pairs unflagged. Separately, the missing-mandatory-source default is `insufficient` in Example 9 and Q16, but `_status` returns `partial` when useful evidence remains. Packing can fail to reserve both witnesses, then include one during ordinary filling and omit the conflict flag; I reproduced that behavior.  
   **Change:** publish one decision-specific transition matrix covering uncertainty, invalid output, denied/failed dependencies, and budget exhaustion. Retain conflict records when witnesses do not fit, with explicit omissions and an appropriate status. [HLD §6.4](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/hld.md:314); [providers §12](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/system-one-providers.md:190); [contracts, Example 9](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/contracts-and-scenarios.md:367); [pipeline.py, `_status`](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/pipeline.py:483); [assembly.py, `pack`](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/assembly.py:228)

3. **High — Independent D2 probabilities do not define a subset-selection policy.** “Necessary evidence from this source” depends on what other sources will supply, requested authority roles, and the retrieval plan. The interface instead asks independent questions over descriptors, and the router thresholds each optional source independently. Required sources are correctly protected, but complementary coverage and correlated omissions remain unspecified.  
   **Change:** distinguish source-support probability from marginal value given a proposed source set. Specify deterministic selection constraints, minimum coverage, uncertainty handling, and bounded exploration. This can remain a small planner around independent predictions; it need not become a model-generated route. **2. Knowledge-memory layer**

1. **High — Release pinning provides configuration consistency, not correctness under concurrent change.** The HLD release includes registry, authority, descriptors, thresholds, and calibration. The lab pins vocabulary/procedures, loads the registry separately, and obtains provider descriptors/calibration separately. Its change feed handles only unsharing and renaming, is consumed before the request, and accumulates invalidations without release-relative rebinding. Feed errors become an empty event list. These mechanisms cannot distinguish “unchanged” from “freshness unknown,” or handle a revocation/change between resolution, retrieval, inference, and response.  
   **Change:** make releases content-addressed dependency closures; pair them with a live policy epoch and source snapshot/version tokens where available. Specify feed watermark/gap detection, reconciliation, freshness limits, and rechecks before egress. When a coherent source read cannot be guaranteed, expose uncertainty. 2. **High — Governance is credible as a workflow, but not yet as an enforceable assertion model.** The design requires dual ownership approval for identity, scoped delegation, dependency validation, and versioned membership. `TermRecord` carries one unrestricted `reviewed_by` string; membership is an unversioned list on an entity; procedures lack applicability scope and dependencies. `load_release` validates some dangling references, but not reviewer authority, identity uniqueness, procedure capabilities, or lifecycle eligibility.  
   **Change:** define a common assertion envelope containing namespace, applicability, metadata permission, provenance, reviewer identities/delegations, dependencies, and lifecycle. Validate publication against that envelope. Governance can remain a simple owner-operated publication process; an autonomous improvement service is unnecessary for v0. [memory §§9.4, 9.7, 9.9](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/memory-design.md:369); [memory.py, records and loader](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/memory.py:36); [r1 identity records](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/owners/memory_seed/r1/release.yaml:237)

   **Change:** distinguish assertion storage, routing observations, retained evidence, and inference replay, each with access and erasure rules. Preserve the independent availability boundary from Engram. **3. Ontology and hub-agnosticism**

1. **High — The ontology is broadly hub-neutral; identity and replay capabilities are not sufficiently negotiated.** Numeric ticket IDs can be represented as source-namespaced native IDs without adding ontology types. A vector store can supply logical selectors without paths. A chat archive lacking stable IDs needs adapter-issued snapshot identities and explicitly limited replay. Today, the HLD requires stable term/artifact identities, while the lab assumes normalized `artifact_id`, `version`, text, and search-then-fetch results; absent versions become the string `"None"`.  
   **Change:** add capabilities for identity stability, addressability, immutable version reads, snapshot retention, and selector semantics. Permit honest partial support. Do not fabricate native stability or universal replay. [memory §8.6](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/memory-design.md:134); [adapter contract §12.3](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/contracts-and-scenarios.md:679); [adapters.py, normalization](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/adapters.py:70); [pipeline.py, hit identity](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/pipeline.py:411)

2. **High — Metadata visibility is inferred from readable places rather than independently authorized assertions.** `entity_visible` requires an accessible place whose manifest domain is not `any`. Consequently, a hub with only universal collections or no native places cannot establish entity visibility through this path. Conversely, visibility through one source permits lookup/use of names supplied by another source; the native term’s metadata permission is not checked.  
   **Change:** authorize entities and assertions directly. Keep namespace, assertion applicability, and metadata permission separate, as the HLD already requires. Readable storage locations should not serve as proof of name visibility. [memory §9.2](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/memory-design.md:317); [resolution.py, `entity_visible` and `resolve`](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/resolution.py:66); [resolution.py, alias selection](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/resolution.py:187)

   **Change:** adapters should declare typed filters and attributed subject bindings; assembly should consume canonical subject references with provenance. Preserve unknown subjects instead of treating missing identity fields as compatible with every subject. [memory §§8.5–8.7](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/design/intelligence-layer/memory-design.md:94); [assembly.py, subject rules](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/assembly.py:160); [resolution.py, `compatible`](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_ref/resolution.py:161); [round3_state.py, role map](/Users/arunmenon/projects/sanctum/sanctum-lab-m0/src/sanctum_run/round3_state.py:39)

**5. System One strategy and meta-taxonomy fidelity**

1. **High — Calibration is necessary, but activation needs decision-specific economic gates.** Shadowing, local calibration, provider-specific bindings, and harmful-omission measurement are appropriate. They do not establish that inference is worth paying for. The completed campaign’s D2 source-prior control is competitive; D6 cannot recover pairs never generated; the live D4 arm changes order without improving success/recall.
